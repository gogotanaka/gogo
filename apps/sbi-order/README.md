# sbi-order — SBI証券 指値注文の自動発注・約定通知

指定した銘柄・株数・価格で成行/指値注文を出し、約定したら macOS 通知で知らせる。
**「いつ・いくら買うか」の判断は人間が行う前提**で、発注操作と約定確認だけを自動化する
（価格条件を見て自動で買い判断をするロジックはこのアプリのスコープ外）。

設計の背景・調査した規制まわりの話は [docs/adr/0001-sbi-order-automation.md](../../docs/adr/0001-sbi-order-automation.md) 参照。

## 前提として承知しておくこと

- SBI証券は個人向けの現物株API を提供していない。このツールはブラウザ自動化
  （Playwright）で SBI の Web サイトを人間の代わりに操作する
- SBI証券の約款第17条（非承認ツール・過大アクセスの禁止）に抵触するリスクがあり、
  最悪の場合アカウントが強制解約されうる。刑事罰の話ではなく契約上の措置
- 認証情報（`config/.env`）は平文で端末に置かれる。端末が侵害された場合の漏洩リスクを承知しておくこと
- パスキーは自動化していない・できない。ログインは ID/パスワードで行う
- 想定外の画面（デバイス認証・エラー等）が出たら自動突破せず処理を止める。
  ブラウザは既定で画面表示ありなので、その場で人間が操作を引き継いで解決する

## セットアップ

```sh
cd apps/sbi-order
pip3 install -r requirements.txt
playwright install chromium
mkdir -p config && chmod 700 config
```

`config/.env` を作成する（`config/` は `.gitignore` 済みなのでコミットされない）:

```sh
SBI_USER_ID=ログインID
SBI_LOGIN_PASSWORD=ログインパスワード
SBI_TRADE_PASSWORD=取引パスワード   # 注文確認画面で聞かれる場合のみ使う。無ければ省略可
SBI_HEADLESS=false                  # 既定で画面表示あり。動作確認後 true に変更可
```

## セレクタの差し替えが必須

ログイン画面・注文入力画面・注文照会画面は認証必須のため、実物を見ずに `sbi_client.py` を
書いている。`NEEDS_SELECTORS` とコメントが付いている箇所は全部プレースホルダーで、
このままでは動かない。以下の手順で実際のセレクタに差し替えること。

```sh
playwright codegen https://site1.sbisec.co.jp/ETGate
```

開いたブラウザで実際にログイン → 何か1つ買い注文を入力 → 確認画面まで自分の手で操作する。
Codegen ウィンドウに生成される `page.get_by_role(...)` / `page.locator(...)` 等のコードを、
`sbi_client.py` の対応箇所（`_is_logged_in` / `_login` / `place_order` / `check_order_status`）
にコピーしてくる。特に以下は要確認:

- ログイン画面がパスキーを優先表示する場合、「ユーザーネームでログイン」等への切り替えが要る
- 注文確認画面で取引パスワードが求められるかどうか（求められる前提のコードにしてある）
- 発注後の確認画面のどこに注文番号が出るか
- 注文照会画面での「約定」判定の文言・場所

## 使い方

```sh
python3 web.py
```

`http://localhost:8381` を開き、銘柄コード・売買・株数・指値価格を入力して発注する。
発注はキューに積まれ、専用スレッドが順番に1件ずつ SBI 上で実行する（同一ブラウザ
セッションを使い回すため、複数注文を同時並行では処理しない）。60秒おきに未約定の
注文を確認し、約定を検知したら macOS 通知を出す。

## 構成

| ファイル | 役割 |
|---|---|
| `sbi_client.py` | Playwright によるログイン・発注・約定確認（要セレクタ調整） |
| `order_store.py` | 発注記録の永続化（SQLite, `config/orders.db`） |
| `notify.py` | macOS 通知（`osascript`） |
| `web.py` | ローカルWeb UI + 発注ワーカー + 約定ポーラー |

## 既知の制約

- 価格・板情報は SBI の認証済みセッションから見る前提（外部の株価APIは使っていない）
- ログインセッションは無操作60分程度で切れるとみられるため、しばらく間隔が空くと
  次の発注時に再ログインが走る（`ensure_logged_in` が毎回状態を確認する）
- 5%を超えて保有する場合は大量保有報告書、取得割合次第ではTOB規制など、
  このツールの外側で別途の法規制がかかる。対象・規模次第では専門家への相談が前提になる
