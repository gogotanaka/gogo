# 0005: 板情報通知への切り替えと、初の実発注

## Status

Accepted (2026-08-17)

## Context

ユーザーから2点の依頼があった:

1. Slack通知は現在値だけでなく板情報（気配値）にしてほしい
2. 実験として、はてな(3930)の買い板の一番（最良買気配）に200株の指値買い注文を
   実際に入れてほしい

## Decision

**板情報通知**

- `sbi_client.py` に `get_order_book(ticker)` を追加。個別銘柄ページの
  「売気配株数／気配値／買気配株数」テーブルを構造化データとして取得する。
  `get_price` 同様、値が非同期に読み込まれるため "--" プレースホルダから実データに
  変わるまでポーリングする実装にした
- `best_bid(ticker)` で最良買気配（価格・数量）を取得できるようにした
- `format_order_book()` でSlack投稿用の等幅テキストに整形する
- `web.py` の株価ポーラーを `get_price` から `get_order_book` + Slack投稿に差し替えた

**初の実発注**

- 発注直前に `best_bid('3930')` で最良買気配を確認 → 742円・100株だった
- `place_order` でフォーム入力 → 確認画面（`#botton1` クリック）→ここで
  「取引パスワードが入力されていません」エラーに遭遇。取引パスワードは注文入力画面側
  （確認画面に進む前）で入力する必要があることが分かった
- ユーザーから実際の取引パスワードをチャットで直接渡され、「保存してよい」との明示的な
  指示があったため、`config/.env` の `SBI_TRADE_PASSWORD` に保存した（`config/` は
  gitignore済み、パーミッション600）
- 確認画面の内容（はてな 3930・現物買・200株・指値742円・概算約定代金148,400円・
  手数料0円）を表示してユーザーに報告した上で、最終発注ボタン
  （`a:has(img[alt='注文発注'])`、確認画面側にはidが振られていない）をクリックし、
  実際に発注した
- 結果: 「ご注文を受け付けました」、注文番号487。この情報をもとに `place_order` を
  完成させ、`sbi_client.py` のdocstringから「未確認」の注記を外した
- この注文はローカルDB（`order_store`）にも手動で記録し、以後は通常の約定ポーラー
  （60秒間隔）で状態を追跡する

## Consequences

- `place_order` は今後、`SBI_TRADE_PASSWORD` が設定されていれば実際に注文を発注できる
  （フォーム入力だけで止まる旧仕様を廃止）。誤発注防止のため「注文確認画面を省略」
  チェックボックスは操作していない（常にオフ＝確認画面を必ず経由する）
- 取引パスワードが平文で `config/.env` に保存されている。ログインID/パスワードは
  依然として自動化しておらず人間が普段のブラウザで行う設計のままだが、発注そのものは
  取引パスワードさえあれば無人で完了できる状態になった。0001で識別したToSリスク・
  漏洩リスクは、この変更でより現実的なものになっている（実際に無人発注が可能になった
  ため）ことを記録しておく
- 板情報のSlack通知により、単純な現在値より詳細な情報が20〜30分おきに流れるように
  なった。板は値動きが早いので、通知時点と実際に見るタイミングでズレることがある
