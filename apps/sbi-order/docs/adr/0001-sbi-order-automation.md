# 0001: SBI証券 指値注文の自動発注・約定通知ツール

## Status

Accepted (2026-08-17)

## Context

「特定の株をSBI証券でちまちま買い集めたい、パスキーログイン＋半自動も可」という依頼から出発した。
実装前に以下を調査し、当初想定と実際の制度・仕様がかなり違うことが分かった。

**SBI証券の自動化まわり**
- 現物株式向けの一般公開APIはない（先物・オプション向けAPIはあるが対象外）
- 約款・規程集 第17条は「当社が認容するツール以外の使用」「過大なアクセス」を理由に
  利用停止・強制解約ができる旨を定める。ブラウザ自動化はここに抵触しうる
  （行政処分・刑事罰ではなく契約上の措置＝最悪でも強制解約という位置づけ）
- パスキーは端末に紐づく生体認証であり自動化できない（すべきでもない）。
  ID/PW ログインは 2026/6/30 のパスキー原則必須化後も引き続き利用可能
- ログインセッションは無操作 60 分程度で切れるとみられ、「最初に1回ログインすれば
  あとは自動で回り続ける」という前提は成立しない
- ログインとは別に、発注時に「取引パスワード」の入力が別途必要な可能性が高い

**大量に買い集める場合の法規制**（当初「2ヶ月で特定銘柄の30%を非公開で取得したい」
という話が出たため調査）
- 5%超保有で5営業日以内に大量保有報告書（EDINETで公開）の提出義務が発生。
  個人が経営に影響を与える目的で取得する場合、月2回の簡易報告で済む「特例報告」は使えない
- 2026年5月1日施行の金商法改正で、TOB規制が「1/3ルール」から「30%ルール」に変更され、
  これまで対象外だった通常の市場内取引（取引所の板で普通に買うこと）も、
  結果として保有割合が30%を超える場合は原則TOB（公開買付け）強制の対象になった
- 対象を「株式会社はてな」で試算したところ、創業者が既に約31.6〜32.5%を保有しており
  30%取得は事実上その争奪になること、平均出来高（1日2.6〜5.2万株）に対し
  2ヶ月で30%（約92万株）を買うのは価格インパクトの観点で非現実的なことも分かった

これらを踏まえ、スコープを「人間が銘柄・株数・価格を都度指定し、発注と約定確認・通知
だけを自動化する」MVPに絞った（自動的に「いつ・いくら買うか」を判断する機能は今回は作らない）。

## Decision

- `apps/sbi-order/` として、このリポジトリの既存アプリ（dashboard, tasker,
  people-reminders, mf-pl）と同じ流儀で作る: 標準ライブラリのみの Python、
  フレームワーク無し、`web.py` をローカルで直接起動するローカルWeb UI
- ブラウザ自動化は Playwright（Chromium, 既定で headed=画面表示あり）。
  ログインは ID/パスワード（パスキーは非対応・自動化しない）
- 認証情報（ログインID/パスワード・取引パスワード）は `apps/sbi-order/config/.env` に平文で置き、
  `.gitignore` 済みの `config/` 配下に隔離する（ユーザー指定）
- 価格・板情報は外部APIではなく、SBIの認証済みセッション自体から取得する（ユーザー指定。
  外部APIより ToS 上の「過大なアクセス」リスクは上がるが、実際の板を見たいという要望を優先した）
- スコープはMVP: 「指定した銘柄・株数・価格で注文を出す」「約定したら通知する」のみ。
  価格条件による自動判断・自動売買ロジックは実装しない
- 想定外の画面（デバイス認証・エラー・セレクタ不一致等）が出たら自動で突破しようとせず
  `HumanInterventionRequired` 例外で止め、人間が headed ブラウザ上で対応する前提にする
  （CAPTCHA・ボット検知を能動的に回避する実装はしない）
- 注文状態はローカル SQLite（`config/orders.db`）に保存し、バックグラウンドスレッドが
  定期的に約定確認、約定時に macOS 通知（`osascript`）を出す

## Consequences

- SBIの利用規約（第17条）に抵触するリスクをユーザーが承知の上で受け入れている。
  実現しうる最悪の結果は強制解約であり、刑事罰や大量保有報告制度・TOB規制とは別の話
- `config/.env` は平文なので、端末が侵害された場合の認証情報漏洩リスクがある。
  SBIの補償免責条項は自己管理不備による漏洩を対象外とする可能性が高い
- ログイン画面・注文入力画面・注文照会画面は認証必須のため、この場では実物を見て
  セレクタを確定できていない。`sbi_client.py` 内の `NEEDS_SELECTORS` と書かれた箇所は
  すべて仮実装であり、`playwright codegen https://site1.sbisec.co.jp/ETGate` を
  ユーザー自身が実行して得た実際のセレクタに差し替える必要がある
- 将来、対象銘柄の5%を超えて保有したくなった場合はこのツールの範囲外で大量保有報告書の
  提出義務が発生する。30%超を狙う場合は市場内取引でもTOBが必要になるため、
  このツールをそのまま無人で回し続けて到達してよい範囲ではない（専門家相談が前提になる）

## Alternatives considered

- 完全無人の自動売買（当初案）: セッションが60分程度で切れることと、発注時に別途
  取引パスワードが要る可能性が高いことから、「ログイン1回だけであとは全自動」という
  前提そのものが崩れていたため今回は採用しなかった
- 外部の無料株価APIで価格監視: ユーザーが実際の板情報を見たいと明言したため不採用
- 現物株API連携: SBI証券は個人向けの現物株API を提供していないため選択肢に無かった
