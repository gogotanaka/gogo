# 0015: 注文照会スクレイピングの実画面知見と約定株数の取り方

## Status

Accepted (2026-08-20)

## Context

リビッド系機能（`0014`）は「未約定注文の列挙」「取消」「約定（部分約定含む）の
把握」を注文照会画面のスクレイピングに依存する。2026-08-20 の運用と実画面
ダンプ・多角レビューで、従来実装の誤りと画面仕様が確定した。

## 実画面で確認した仕様（2026-08-20）

1. **既定フィルタ「注文中・待機中」は約定済み・取消済み・失効の行を隠す**。
   実際に、全部約定間際の注文529が既定表示から消え、旧ポーラー
   （`check_order_status`）が 'unknown' 扱いにして追跡を打ち切っていた。
   全行を見るには毎回「全ての注文」リンクをクリックする必要がある
   （フィルタはページ遷移で既定に戻る）
2. **1論理行の構造**: 注文番号行（td[0]=注文番号, td[1]=注文状況,
   td[3]=銘柄セル「はてな 3930 東証」…）+ 詳細行（td[2]=注文株数（未約定）
   例 `600 (600)`）+ **約定明細行**（約定が発生した場合のみ。
   `約定 | 市場 | 約定日時 | 約定株数 | 約定単価` が1約定につき1行）
3. 注文状況の文字列は `注文中` / `取消完了` / `取消完了(一部約定)` 等。
   取消と約定が併記されるため、**取消・失効の判定を約定より先に**行う
4. 「注文株数（未約定）」セルの `qty (unfilled)` 書式は **注文中の行でのみ検証済み**。
   取消完了・失効の行での表示仕様（未約定が残数のままか0リセットか）は未確証

## Decision

- `_open_order_inquiry(all_orders=True)` で毎回「全ての注文」に切り替える。
  `read_order_table()` は論理行を構造化し（注文番号・状況・銘柄・
  注文株数/未約定・**約定明細合計 filled_execs**）、以後の状態判定・取消対象の
  列挙・約定株数の把握はすべてこの1回の読み取りのスナップショットから行う
- **約定株数の正は約定明細行の合計**（部分約定・取消後・失効後も残る）。
  「注文株数（未約定）」セルからの逆算は注文中の行に限って併用する。
  未確証の表示（取消済み行のセル等）から推定しない
- 行の特定は **注文番号セルの完全一致**。従来の `tr:has-text('注文番号')` は
  部分文字列一致のため、注文番号が他行の株数（`600 (600)`）・価格（742〜760）・
  銘柄コード（3930）等と衝突すると **別の注文を誤取消 / 状態を誤読** しうる
  （レビューで確認。注文番号は口座内で単調増加しており、まもなく株数・価格と
  同じ数字帯に到達するため時限爆弾だった）
- ポーラーは注文ごとに照会を開くのをやめ、**1回の読み取りで追跡中の全注文を
  判定**する（`_sync_orders_from_rows`）。約定株数（`orders.filled_qty` 列）を
  先に反映してから終了状態（filled / cancelled / expired）を確定する。
  `失効` は 'expired' として追跡を打ち切る（従来は「取消・約定を含まない」ため
  'submitted' 扱いになり、引け後もポーリングし続けていた）
- リビッドの取消フローは「取消 → 照会を再読み → 反映」とし、取消の直前に
  滑り込んだ約定を確定させる
- 発注（`place_order`）の受付確認は固定1.5秒待ち+一発判定をやめ、受付文言を
  最大15秒待つ。それでも例外になった場合は「受注済みかもしれない」前提で
  照会を再読みし、直前に無かった同銘柄・同株数の新注文が1件だけあれば
  それを自分の注文として採用・追跡する（受注済み注文が誰にも追跡されず
  放置される事故の防止）

## Consequences

- 照会まわりのナビゲーション回数はポーラー1周あたり最大1回に減った
  （従来は追跡注文数ぶん開いていた）
- 取消済み行の「注文株数（未約定）」セルの意味は未確証のまま採用しない方針に
  したため、そのセルにしか現れない情報があっても失わない（約定明細行が正）
- 部分約定の実例（注文530: `取消完了(一部約定)` + 約定明細5行 = 1,200株）で
  約定明細行の構造を確認済み。ただし「注文中のまま部分約定」の行の実例は
  未観測で、その場合の明細行の出方は推定（同じ構造のはず）
