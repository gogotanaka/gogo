# 0014: watch/watch-open コマンド言語の導入とセッション方式の廃止

## Status

Accepted (2026-08-20)

## Context

自動リビッド（rebid = 買い板の一番上の額で買い指値を入れること）の指示方法は
短期間で3回変わった:

1. env設定（`SBI_AUTO_REBID_TICKER` 等）による常時リビッド。数量300〜600株
   ランダム・20〜30分間隔・価格上限つき
2. `start 銘柄 合計株数 上限価格` / `stop` メンションによる「リビッドセッション」。
   目標株数に達したら終了。開始は8:59〜9:05限定 → その後「いつでも受付・次の
   8:59開始の予約」に変更
3. ユーザーによるコマンド言語の確定（本ADR）

2 の運用初日（2026-08-20 8:59）に、ツールの注文がユーザー自身のアプリ操作で
取り消され、別注文で1,200株が手動約定するという「ツールと人間の並走」が起き、
目標株数ベースの会計（残量 = 目標 − ツールの買付済み）はツール外の売買と
相性が悪いことが分かった。また同日のレビューで、残量会計は部分約定の
取りこぼし・日またぎ・発注直後のクラッシュ等で「買い過ぎ/買い逃し」に
直結する欠陥群が確認された（詳細は `0015`）。

ユーザーが確定させた言語は目標株数を持たない:

```
rebid:      買い板の一番上の額で買いを入れること（概念）

buy 3930 300 744        一回きりの買い注文
sell 3930 300 744       一回きりの売り注文
watch 3930 400 760 900  平均400株(±30%ランダム)・上限760円で、rebidを
                        平均900秒(±30%ランダム)間隔で実行し続ける
watch-open buy 3930 400 760
                        毎営業日8:59〜9:05の間、20秒毎にrebid（寄り付き用）。
                        一度設定されたら毎朝実行
clear-all               注文を全て消す
```

## Decision

- `start`/`stop` セッション（目標株数・残量会計・予約日）を廃止し、
  `watch` / `watch-open` を **銘柄ごとの常設設定** として `config/watches.json` に
  永続化する（`watch_store.py`）。解除コマンドは言語に無かったが運用上必須なので
  `unwatch 銘柄` / `unwatch-open 銘柄` を追加した
- **目標株数・買付済み会計は持たない**。各ティックは「その銘柄の未約定注文を
  取消 → 最良買気配に新しい注文」を置くだけで、過去の約定量は発注判断に使わない。
  これにより残量会計に起因する買い過ぎ/買い逃しの欠陥クラスが構造的に消える。
  約定株数の追跡は続ける（Slack報告と web UI の「本日約定」表示用。`0015`）
- **watch は止めるまで買い続ける**。総量の歯止めは (1) 1注文あたりの
  `SBI_MAX_ORDER_VALUE_YEN`、(2) 毎ティックのSlackメンション報告、(3) ユーザーの
  `unwatch`。これはユーザーが明示した仕様（目標株数を言語から外した）である
- 取消の範囲は「その銘柄の注文中の注文」のみ（旧実装は全銘柄を取り消していた）。
  銘柄ごとのwatchが互いの注文を消さないようにするため
- watch と watch-open が同一銘柄に設定されている場合、watch-open だけを実行し、
  watch は設定を残したまま休止する（unwatch-open で再開）。当初は「8:59〜9:05の
  窓の間だけ watch-open 優先」だったが、2026-08-21 にユーザー指定で
  「両方あるときは watch-open のみ」へ変更した。互いに相手の注文を取り消して
  しまう問題も、この単純な排他で同時に解消される
- watch-open は20秒間隔だが、**自分の注文が既に最良買気配と同値で並んでいる場合は
  何もしない**（取消→再発注は板の待ち順を失うだけ）。この最適化により20秒間隔が
  実用になる（1回のrebidはページ遷移で数十秒かかることがある）
- 数量・間隔の±30%ランダムは、既存の板取得間隔のランダム化と同じく機械的な
  アクセスパターンを避けるため（ユーザー指定の仕様でもある）
- 設定・解除はHTTPスレッドがファイルを書くだけ。`_sbi_loop` は `updated_at` の
  変化で新規/置き換えを検知して場中なら即時ティックする。ティック実行中の
  置き換え/解除は、発注直前の `still_valid()` 再確認で検知して発注を中断する
  （ティックは数十秒かかるため、設定変更との交錯は現実に起きる。`0016`）
- 今のwatch状況（設定・直近の気配・直近アクション・本日約定）を表示する
  web UI を `http://localhost:8381` に追加した（30秒ごと自動リロード）。
  発注フォーム・注文履歴と同居

## Consequences

- Slackコマンドは `buy`/`sell`/`watch`/`watch-open`/`unwatch`/`unwatch-open`/
  `clear-all`（旧 `clear all` も互換）/`book` になった。`start`/`stop` は
  書式エラー（USAGE返信）になる
- 「〜株買ったら止める」はできなくなった。必要ならユーザーがSlack報告や
  web UI を見て `unwatch` する運用
- watch-open の設定は毎朝有効なので、消し忘れると翌朝も買いに行く。
  web UI と設定時の返信で「毎営業日実行」であることを明示している
