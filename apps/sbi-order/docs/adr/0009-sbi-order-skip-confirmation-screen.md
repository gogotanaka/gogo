# 0009: 発注時に「注文確認画面を省略」を使う

## Status

Accepted (2026-08-18)

## Context

0001時点で「注文確認画面を省略」チェックボックスは絶対にチェックしない、と決めていた
（誤発注防止のため）。ユーザーから「注文確認画面を省略したい感じがある」という指摘が
あり、改めて検討した。

このチェックボックスによる確認画面は、`place_order` の実装上は「エラーが無いかを
機械的に判定するだけの中間チェックポイント」でしかなく、人間が内容を見て承認して
いるわけではなかった（`self.page.get_by_text("注文確認", ...)` の有無を見て
先に進むかどうかを決めているだけ）。つまり誤発注防止としての実効性はほぼ無く、
単にHTTPラウンドトリップを1回増やしていただけだった。

## Decision

- `place_order` で「注文確認画面を省略」（id=`shouryaku`）を常にチェックするように
  変更した。これにより「注文確認画面へ」ボタン（id=`botton1`）は非表示になり、
  最終発注ボタン（id=`botton2`）がその場で有効になるため、確認画面を経由せず
  1回のクリックで発注が完了する
- 実際に実画面でテスト（はてな3930、100株、指値650円、注文番号498）し、
  正常に発注・その後の取消ができることを確認した
- 途中、指値500円（当日の値幅制限593〜893円を下回る）で試したところ
  「注文価格が制限値幅を超えています」というエラーが発注入力画面上に表示される
  ことも確認した。省略しても、SBI側のバリデーション自体は引き続き機能する
- エラー検知は「ご注文を受け付けました」の有無で判定する点は変わらないが、
  検知できなかった場合のメッセージに、ページ本文冒頭のスニペットを含めるように
  改善した（何のエラーだったかSlack通知等から推測しやすくするため）

## Consequences

- 発注のレイテンシが1往復分（数百ms〜1秒程度）短縮される
- 「確認画面を経由しない」こと自体による安全性の低下はほぼ無い（元々人間が確認画面を
  見ていたわけではないため）。ただし本質的に「フォーム入力ミス→即発注」までの距離が
  縮まったのは事実であり、上位の安全策（`SBI_MAX_ORDER_VALUE_YEN`、厳密な
  コマンド書式、送信者制限）の重要性が相対的に増している
